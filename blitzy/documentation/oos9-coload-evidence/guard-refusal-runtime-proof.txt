# OOS-9 Outcome A - runtime proof of the guard AS SHIPPED

Re-captured against the binaries this branch installs, so every line number, log anchor and
banner below is the SHIPPED revision rather than the first revision of the guard.  Three
scenarios, each in a fresh disposable instance with its own conf/log/db/run/temp/cache/storage
copy and its own event-socket port 28041.  The installed configuration under
/usr/local/freeswitch/conf was not modified, no tracked file was touched, and only the pid each
run started was ever signalled.

WHY THREE SCENARIOS AND NOT TWO.  The guard has two stages and they refuse for different
reasons, so a proof of one is not a proof of the other:

  stage 1  switch_loadable_module_exists(<sibling>)         mod_h323.cpp:198 / mod_opal.cpp:145
           refuses when the sibling is in the module hash - the sequential, common case.
           Proven by scenarios 1 and 2.
  stage 2  switch_core_set_var_conditional(<RESERVATION>,   mod_h323.cpp:221 / mod_opal.cpp:169
           modname, "")
           refuses when the process-global PTLib reservation is already held even though the
           sibling is NOT in the hash - the state a losing concurrent claimant sees, and the
           one stage 1 cannot see.  Proven by scenario 3, which reaches it by planting the
           reservation while the sibling is absent, and asserts that absence so the refusal
           cannot be attributed to stage 1.

The four observables the directive requires are labelled inline in every scenario.  Each
capture also ends with the mod_xml_curl fallback-event subclass release, because it is the one
line that shows the core taking its OWNER-MATCHED branch ("Subclass reservation deleted for
mod_xml_curl.c:...") rather than the non-owner "inuse by listeners, detaching.." branch - the
distinction the module's shutdown guard exists to preserve.

mod_signalwire is deliberately not loaded in these instances.  It prints a per-installation
adoption token at NOTICE on its not-yet-adopted branch, and a verbatim capture is no place for
one; see signalwire-token-rotation.txt.
